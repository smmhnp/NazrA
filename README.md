# موسسه آموزش عالی شاندیز | نهضت هر شب جمعه

وباپ فارسی، کاملاً RTL، موبایلمحور و **قابل اجرا بهصورت آفلاین** برای ایام فاطمیه.
خروجی، یک پروژهٔ واقعی و قابلاجراست (نه طرح گرافیکی): تمام مسیرها، آزمون، تولید کارت،
اشتراکگذاری و ذخیرهسازی محلی کار میکنند. **لوگوی رسمی موسسه** قرار گرفته است.

> ⚠️ **وضعیت: پیش از انتشار.** ایمیل، آدرس و ساعت موکب و بخش زیادی از متنها
> عمداً با `TODO` مشخص شدهاند. هیچ متن تأییدنشده بهعنوان حدیث، آیه، خاطرهٔ واقعی،
> سخن معصوم یا نقل قول تاریخی معرفی نمیشود. پیش از انتشار حتماً
> [فهرست TODOها](#todo-های-الزامی-پیش-از-انتشار) را تکمیل کنید.

## ۱. ویژگیها

- **بدون بکاند، بدون API، بدون سرویس پولی، بدون هیچ وابستگی اجرایی.** فقط HTML/CSS/JS ES Modules.
- **حریم خصوصی کامل:** عکس سلفی فقط روی همان دستگاه و در Canvas پردازش میشود؛
  هیچ درخواست شبکهای، ابزار تحلیلی یا ذخیرهسازی ابری وجود ندارد.
- **PWA قابل نصب و آفلاین:** `manifest.json` + Service Worker نسخهدار با کش فونت، CSS، JS، لوگو و آیکونها.
- **محتوای مسئولانه:** اعتبارسنجی زمان اجرا در `js/lib/validation.js`؛ رکوردهای `TODO` با برچسب
  «نمونهٔ نیازمند تأیید منبع» نمایش داده میشوند و متنهای تدوینی صریحاً «نقل قول یا حدیث نیست» خوانده میشوند.
- **موتور کارت مشترک:** هر ۹ ترکیب (۳ قالب × کارتپستال/سلفی/آزمون) با یک `renderCard` و پیکربندی دادهمحور،
  خروجی PNG دقیقاً `1080×1350` (نسبت ۴:۵) میدهد.
- **صفحهٔ پایانی خلوت:** کارت شمارش معکوس بنا به درخواست حذف شده و بین سکشنها فاصلهٔ یکنواخت
  وجود دارد. ساعت برگزاری همچنان از `config.js` خوانده میشود و تا تأییدنشدن، پیام «بهزودی اعلام میشود» نشان داده میشود.
  منطق محاسبهٔ زمان/منطقهٔ زمانی/DST در `js/lib/time.js` باقی مانده وتست واحد میشود.

صفحهٔ پایانی و دعوت به موکب. دکمهٔ «رد کردن و ادامه» در تمام مراحل فعالیتها وجود دارد.

## ۳. اجرای محلی

پیشنیاز: **Node.js 18+** (فقط برای سرور توسعه و تستها). خود اپ در مرورگر بدون هیچ وابستهای اجرا میشود.

```bash
git clone <your-repo-url> NazrA
cd NazrA
npm install          # اختیاری؛ فقط برای تستها و تولید آیکونها
npm start            # http://localhost:4173
```

بدون npm هم میتوانید از هر سرور ایستای سادهای استفاده کنید (Service Worker فقط روی
`localhost` یا **HTTPS** کار میکند، نه روی `file://`):

```bash
python3 -m http.server 4173 --bind 0.0.0.0
# سپس http://localhost:4173
```

> سرور توسعه (`npm start`) برای HTML/CSS/JS سرصفحهٔ `Cache-Control: no-store` میفرستد و
> Service Worker در `localhost` از استراتژی network-first استفاده میکند؛ بنابراین
> هنگام توسعه فایلهای قدیمی کش نمیشوند.

### اسکریپتها

| دستور | کار |
| --- | --- |
| `npm start` / `npm run dev` | سرور توسعه روی پورت `4173` (قابل تغییر با `PORT=8080 npm start`) |
| `npm test` | اجرای تمام تستها (واحد، یکپارچه، موتور کارت، صحتسنجی فایلها) |
| `npm run check` | بررسی هماهنگی نسخهٔ کش + اجرای تستها |
| `npm run sw:version` | **بعد از هر تغییر در فایلهای app shell** نسخهٔ کش را از روی هش فایلها بروزرسانی میکند |
| `npm run build` | ساخت پوشهٔ `dist/` فقط از فایلهای لازم انتشار |
| `npm run icons` | پردازش دوبارهٔ لوگو و بازتولید آیکونهای PWA (نیازمند `npm install`) |

## ۴. استقرار

هیچ مرحلهٔ bundler/minifier وجود ندارد. همهٔ مسیرها **نسبی** (`./`) هستند،
پس اپ هم در ریشه (`https://example.com/`) و هم در زیرمسیر
(`https://user.github.io/NazrA/`) بدون تغییر کار میکند. `start_url`, `scope` و
محدودهٔ Service Worker نیز `./` هستند.

### الف) GitHub Pages (پیشنهادی — خودکار)

۱. مخزن را در GitHub بسازید و شاخهٔ `main` را پوش کنید.
۲. در `Settings → Pages`، گزینهٔ **Source** را روی **GitHub Actions** قرار دهید.
۳. فایل `.github/workflows/deploy-pages.yml` موجود در مخزن، در هر پوش:
   - نسخهٔ کش را بررسی میکند،
   - `npm run build` را اجرا میکند (خروجی `dist`، فقط ۳۳ فایل لازم)،
   - و آن را به Pages منتشر میکند.

چون خروجی در زیرمسیر `/NazrA/` سرو میشود، `sw.js` همان `scope: './'` را خواهد داشت.
اگر میخواهید از شاخهٔ `gh-pages` استفاده کنید، محتوای `dist/` را در ریشهٔ آن شاخه قرار دهید.

### ب) GitHub Pages (ساده، از ریشهٔ مخزن)

در `Settings → Pages → Deploy from a branch` شاخهٔ `main` و پوشهٔ `/ (root)` را انتخاب کنید.
همین فایلها سرو میشوند؛ فقط دقت کنید `sw.js` و `manifest.json` در ریشه باشند.
پیش از هر استقرار `npm run sw:version` را اجرا و `sw.js` را کامیت کنید.

### ج) Netlify

۱. مخزن را به Netlify متصل کنید.
۲. `netlify.toml` موجود بهطور خودکار خوانده میشود:
   - `command = node scripts/build-static.mjs`
   - `publish = dist`
   - سرصفحهٔ `Cache-Control: no-cache` برای `sw.js` و `Service-Worker-Allowed: /`.
۳. یا بهصورت دستی: `npm run build` سپس پوشهٔ `dist/` را در **Netlify Drop** رها کنید.

### د) هر هاست ایستای دیگر

`npm run build` → محتوای `dist/` را روی هاست (Cloudflare Pages، Vercel static،
Apache/Nginx، S3+CloudFront و…) قرار دهید. فقط الزامی است که سرویس روی **HTTPS**
باشد تا Service Worker و Web Share API قابل استفاده باشند.

> **نسخهٔ کش:** نام کش `nazra-static-<hash>` است. با هر تغییر در فونت/CSS/JS/HTML،
> `npm run sw:version` را اجرا کنید؛ در غیر اینصورت `npm run check` و CI خطا میدهند.
> Service Worker هنگام `activate` کشهای قدیمی را پاک میکند.

## ۵. تنظیمات و محتوا

همهچیز در `js/config.js`:

| کلید | مقدار فعلی | توضیح |
| --- | --- | --- |
| `universityName` | موسسه آموزش عالی شاندیز | نام نمایشدادهشده در سربرگ، صفحهٔ آغازین و کارتها |
| `logoPath` | `./assets/logo.png` | نسخهٔ شفاف لوگوی رسمی؛ توسط `npm run icons` از `logo-source.png` ساخته میشود |
| `NEHZAT_EMAIL` | `TODO` | اگر معتبر نباشد، لینک `mailto:` ساخته **نمیشود** |
| `mosqueAddress` | `TODO` | آدرس دقیق موکب |
| `eventTime` | `TODO` | `HH:MM` به وقت محلی؛ تا معتبر نباشد «ساعت برگزاری بهزودی اعلام میشود» نمایش داده میشود |
| `timeZone` | `Asia/Tehran` | نام IANA؛ صریح و قابل تنظیم |
| `eventDayOfWeek` | `4` | پنجشنبه = شب جمعه (`۰`=یکشنبه … `۶`=شنبه) |
| `brand` | پالت رنگ | رنگهای CSS باید با مقادیر برند هماهنگ بمانند |
| `card.footerLine` | `شب جمعه، موکب …` | متن کوچک پایین همهٔ کارتها؛ نام مکانی ادعا نمیشود |
| `privacy.*` | متن اعلامیه و سقف حجم عکس | پیام حریم خصوصی و محدودیت ۱۵ مگابایت |

`js/content.js` شامل `CATEGORIES`, `TEXT_RECORDS`, `QUESTION_RECORDS`, `CARD_TEMPLATES`,
`QUIZ_MESSAGES`, `COPY` است. ساختار هر رکورد متن:

```js
{
  id: "TODO_scientific_001",
  category: "scientific",
  text: "TODO — ...",
  source: "TODO — منبع دقیق و قابل بررسی",
  sourceUrl: null,          // فقط http(s) معتبر پذیرفته میشود
  verified: false,
  sourceType: "placeholder" // placeholder | editorial | app-doc
}
```

و هر پرسش: `{ id, category, question, options[4], correctIndex, explanation, source, sourceUrl, verified, sourceType }`.
**پاسخ صحیح فقط از `correctIndex` خوانده میشود** و هیچ پاسخی در رابط ثابت نشده است.

قواعد ویرایش محتوا:
- رکورد `TODO` را با متن و منبع دقیق جایگزین کنید، `verified: true` و `sourceType: "editorial"`
  (برای متن تدوینی) یا یک `sourceType` معتبر قرار دهید. **هرگز** متن بیدلیل را به نام
  معصوم، راوی یا منبع تاریخی ثبت نکنید.
- `verified: false` یا `sourceType: "placeholder"` بهطور خودکار برچسب «نیازمند تأیید منبع» میگیرد.
- رکوردهای ناقص (متن خالی، کمتر از ۴ گزینه، `correctIndex` نامعتبر، `sourceUrl` نامطمئن)
  هنگام اجرا فیلتر شده و در کنسول هشدار داده میشوند.
- `COPY` پیامهای پویا (اعلانها، برچسبها، پیامهای آزمون) را نگهداری میکند.

## ۶. حریم خصوصی

- عکس با `<input type="file" accept="image/*" capture="user">` گرفته میشود،
  سپس با `createImageBitmap` (یا `Image` محلی) **فقط در حافظهٔ همان دستگاه** خوانده میشود.
- هیچ `fetch/XMLHttpRequest/sendBeacon/Analytics/Firebase/SDK` برای دادهٔ کاربر وجود ندارد.
  تنها درخواستهای شبکهای، همان فایلهای استاتیک خود اپ و کش Service Worker هستند.
- `localStorage` فقط مرحله، دسته، شناسهٔ متنهای دیدهشده، پیشرفت آزمون، تنظیمات قالب و
  وضعیت «میآیم» را نگهداری میکند. **عکس اصلی یا فایل PNG ذخیره نمیشود.**
- دکمهٔ «میآیم» فقط یک **نشانگر شخصی** روی همان دستگاه است؛ ثبتنام یا اعلام حضور به
  برگزارکنندگان انجام نمیشود (این جمله زیر دکمه نوشته شده است).
- منابع خارجی (`sourceUrl`) بهصورت پیشفرض `null` هستند؛ اگر بعداً مقداردهی شوند،
  فقط لینک `http(s)` معتبر پذیرفته میشود و در حالت آفلاین بهجای لینک شکسته، هشدار نشان داده میشود.

## ۷. محدودیتهای مرورگر

| قابلیت | محدودیت |
| --- | --- |
| نصب PWA / Service Worker | فقط **HTTPS** یا `localhost`. روی `file://` یا HTTP غیرمحلی غیرفعال است. iOS از طریق «Add to Home Screen» نصب میکند و برخی APIها (Push، Background Sync) را محدودتر پیادهسازی میکند. |
| آفلاین | نیازمند **یک بار بازدید آنلاین** تا Service Worker فایلها را کش کند. اگر کش نصب نشده باشد، صفحهٔ آفلاین اختصاصی با دکمهٔ «تلاش دوباره» نمایش داده میشود. |
| دوربین | `capture="user"` فقط یک **پیشنهاد** است؛ برخی مرورگرها/سیستمعاملها همچنان فقط گالری یا دوربین عقب را باز میکنند. لغو انتخاب خطا ایجاد نمیکند. فایلهای بسیار بزرگ (>۱۵MB) یا فرمتهای ناشناخته (مثلاً HEIC در برخی مرورگرها) با پیام مناسب رد میشوند. |
| Web Share API | `navigator.canShare({files})` معمولاً فقط در Chrome/Edge اندروید و Safari جدید پشتیبانی میشود. در سایر مرورگرها کارت **دانلود** میشود، سپس در صورت تنظیمبودن ایمیل، `mailto:` باز میشود و پیام «عکس را به پیام پیوست کنید» نشان داده میشود. لغو توسط کاربر (`AbortError`) از خطا جدا شده است. |
| mailto | نیازمند برنامهای ایمیل نصبشده روی دستگاه است. اگر `NEHZAT_EMAIL` معتبر نباشد، لینک ناقص ساخته نمیشود. |
| کپی (Clipboard API) | در زمینهٔ امن (HTTPS) و با اجازهٔ مرورگر کار میکند؛ در غیر اینصورت روش قدیمی `execCommand` امتحان میشود و در نهایت متن/لینک بهصورت قابل انتخاب نمایش داده میشود. |
| Canvas / PNG | `canvas.toBlob` در مرورگرهای قدیمی پشتیبانی نمیشود (روش جایگزین `toDataURL` تعبیه شده). تصاویر بسیار بزرگ ممکن است در دستگاههای کمحافظه باعث محدودیت شوند؛ حافظهٔ بوم و URLهای موقت پس از ساخت آزاد میشوند. |
| دانلود | ویژگی `download` روی `<a>` در iOS Safari ممکن است تصویر را در تب جدید باز کند؛ راهنمای «عکس را به پیام پیوست کنید» در همان صفحه نمایش داده میشود. |

### مواردی که امکان تست آنها در این محیط وجود نداشت
